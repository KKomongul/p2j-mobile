# P2J 디자인 시스템

페이퍼컷 로우폴리 에디토리얼. 색종이를 오려 붙인 2.5D 면으로 층을 만들고,
목록과 입력은 평면으로 둬서 빠르게 읽히게 한다.

**팔레트는 마스코트 플랜펭에서 뽑았다.** 네이비 몸통, 라벤더 소품, 앰버 발, 크림 종이.
일러스트가 화면에 얹혔을 때 겉돌지 않는 것이 이 팔레트의 유일한 목적이다.

이 문서는 **지금 코드에 있는 것**과 **아직 없는 것**을 구분해 적는다.
없는 것은 명세만 두고 구현하지 않는다. 서버에 없는 기능은 화면도 만들지 않는다.

### 1.2 스페이싱 · 라운드 — [`app_spacing.dart`](../lib/core/theme/app_spacing.dart)

- 8pt 체계. `s4`는 반 칸으로만 쓴다(칩 안쪽 여백 등).
- 화면 좌우 여백 `screenH = 20`.
- 최소 터치 영역 48dp. 체크박스는 24dp 그림에 패딩으로 48dp를 만든다.
- 라운드: `r4`(배지·트랙) · **`r8`(카드·입력·버튼 기본)** · `r16`(바텀시트 상단) · `pill`(**칩과 태그 전용**).
- 카드 안에 카드를 넣지 않는다. 한 화면에 종이 카드는 한두 장.
- 그림자는 `paperShadow` 하나. blur 6, offset (1, 2) — 조명이 좌측 상단에서 온다.

### 1.3 타이포 — [`app_typography.dart`](../lib/core/theme/app_typography.dart)

Pretendard 가변 폰트. Flutter 는 가변 폰트에서 `fontWeight` 를 `wght` 축에
자동으로 이어주지 않으므로 **모든 스타일이 `fontWeight` 와 `fontVariations` 를 함께** 지정한다.

`display` · `numberM` (숫자) / `titleXL` `titleL` `titleM` / `body` `bodyStrong` / `caption` / `label` / `story`(말풍선).

### 1.4 일러스트 규칙

플랜펭은 **화면마다 넣지 않는다.** 다음 순간에만 등장한다.

1. 처음 사용 안내 (인트로·로그인 대화)
2. 할 일이 없는 빈 화면
3. AI가 정리하거나 부담을 조절할 때
4. 목표 달성·연속 기록 축하
5. 오류를 부드럽게 안내할 때

24dp 이하 조작 아이콘은 **Material Symbols Rounded**. 캐릭터를 아이콘으로 쓰지 않는다.

## 2. 정보 구조와 내비게이션

```
비로그인
└─ /onboarding        대화 하나로 가입과 로그인을 모두 처리한다

로그인
└─ StatefulShellRoute (하단 4탭)
   ├─ /home    오늘        ← 기본
   ├─ /goals   목표
   ├─ /group   그룹        목록 → 상세(오늘 · 피드 · 순위)
   └─ /stats   통계
```

그룹 상세는 탭 밖으로 띄운다(`rootNavigator`). 한 그룹 안에 들어가면 하단 탭을 잠시
접어 두는 편이, 그 안의 세 탭(오늘·피드·순위)과 하단 4탭이 겹쳐 보이지 않는다.

`/login` 경로는 없다. 로그인하지 않으면 언제나 `/onboarding` 이다.
인증 판정은 [`app_router.dart`](../lib/core/router/app_router.dart) 의 `redirect` 한 곳에서만 한다.

## 3~4. 화면별 목적 · 행동 · 레이아웃

### 3.1 인트로 / 가입 / 로그인 — **구현됨**

목적: 계획 세우기를 부담스러워하는 사람에게 폼을 들이밀지 않는다.

- 배경 `ink`(네이비) 전면. 말풍선(`paper`) + 마스코트 + 타자기 효과.
- **한 화면에 한 문장, 한 번에 한 가지만** 묻는다.
- 가입: MBTI → 이름 → (자동) 공감 → 약속 → 시작 → 이메일 → 비밀번호
- 로그인: `이미 계정이 있어요` → 다시 만나 반가워요(자동) → 이메일 → 비밀번호
- 이미 가입된 이메일이면 이메일을 다시 묻지 않고 비밀번호 줄로 넘긴다.
- 주요 버튼은 `amber`(네이비 위에서 `ink` 버튼은 묻힌다).
- 키보드가 올라오면 마스코트를 접는다. 말풍선과 입력칸이 먼저다.

### 3.2 오늘 — **구현됨**

목적: 오늘 얼마나 했는지 3초 안에 알고, 다음 할 일을 체크한다.

```
AppBar  오늘                                    [로그아웃]
────────────────────────────────────────────────────────
WeekStrip   화1 수2 목3 금4 토5 일6 [월7]   ← 링이 달성률
────────────────────────────────────────────────────────
TodaySummaryCard  (paper, r8, 높이 ~104dp)
  오늘의 진행                          예상 95분
  25%   4개 중 1개                    [3개 남음]
  ▬▬▬▬░░░░░░░░░░░░░░░░
────────────────────────────────────────────────────────
TodoTile ×N  (평면, divider 구분, 카드 아님)
  ○  백준 실버 2문제                ⚑     [🔒 선언]
     알고리즘 문제 풀기 · 45분 · 3학년 개발조
  ✓  3km 달리기                    ⚑     [📷 인증샷]
     주 3회 운동하기 · 30분 · 러닝조
────────────────────────────────────────────────────────
                                            [ + ] FAB
```

**히어로를 두지 않는다.** 예전 달성률 블록은 화면 절반을 먹었다.
목록이 주인공이고 요약 카드는 머리말이다.

행동: 체크(낙관적 갱신) · 스와이프 삭제 · 날짜 선택 · 추가
· **목표 갈아끼우기(⚑)** · **인증샷 올리기(📷)**.

**목표는 만들 때가 아니라 목록에서 정한다.** 일단 적어 두고 나중에 "이건 그 목표에
넣자" 가 되는 흐름이라, 행의 깃발 버튼이 목표 목록 시트를 연다. 목표를 떼는 것도
같은 시트의 한 줄이다 — 해제를 숨겨 두면 잘못 붙였을 때 되돌릴 길이 안 보인다.
선언한 항목은 서버가 목표 변경을 막으므로 깃발을 흐리게 두고, 눌렀을 때 이유를 말한다.

**부제에 선언한 그룹 이름을 적는다.** 잠긴 이유를 칩 하나로만 알리면 "왜 못 고치지" 가
된다. 상대가 보여야 납득이 된다.

**인증샷은 끝낸 직후에만 나타난다.** 완료 체크 옆이 사진을 올리는 순간이라 동선이
가장 짧다. 그룹 탭까지 들어가지 않아도 되고, 사진 한 장이 선언한 그룹 전부에 올라간다.

### 3.3 할 일 추가와 음성 입력 — **구현됨**

목적: 문장을 다듬지 않고 말한 그대로 던지게 한다.

바텀시트 4단계.

| 모드 | 내용 |
| --- | --- |
| `voice` | 마스코트 + 마이크 버튼. 아래에 `글로 적을게요 · 한 개만 직접` |
| `confirm` | 받아 적은 문장을 보여 주고 `정리해 주세요` / `직접 고칠게요` / `다시 말할게요` |
| `dictate` | 문장을 글로 적어 AI 로 보낸다. **마이크를 못 쓰는 사람도 AI를 쓸 수 있어야 한다** |
| `typing` | 제목 + 소요시간. AI 를 거치지 않는 단건 |

말이 끝나자마자 저장하지 않는다. 잘못 들었을 때 되돌릴 길이 없으면 음성 입력을 안 쓰게 된다.

### 3.4 AI 계획 구조화 및 검토 — **구현됨**

목적: 한 문장을 여러 할 일로 쪼개되, **AI가 틀릴 수 있다는 전제**로 확인을 받는다.

```
이렇게 정리했어요                        [확인 필요]
맞는 것만 남기고 고쳐 주세요.
────────────────────────────────────────────────
☑  보고서 쓰기            ← 제목은 바로 고칠 수 있다
   [내일] [오전]
────────────────────────────────────────────────
☑  헬스장 가서 운동
   [내일] [저녁] [90분]
────────────────────────────────────────────────
☐  장보기
   [9월 11일 (금)]
────────────────────────────────────────────────
             [ 2개 추가하기 ]
```

- `parse_method` 가 `llm` 이면 `[AI 정리]`(purple), `rules`/`none` 이면 `[확인 필요]`(amber).
  AI가 한 게 아닌데 AI가 했다고 말하지 않는다.
- **여기까지 아무것도 저장되지 않는다.** 확인 버튼을 눌러야 `POST /todos/bulk` 로 한 번에 만든다.
- 일 한도를 넘겨 규칙 파서로 내려온 경우 그 사실을 문구로 알린다.

### 3.5 목표 — **목록 · 만들기 구현됨**

목적: 반복 목표를 만들 때 **무엇을 약속하는지 숫자를 채우는 동안 계속 보이게** 한다.

목록은 카드 한 장에 색 점 · 제목 · 진행률 · 이번 주 페이스를 담는다.
목표 색은 제목 앞 점 하나로만 쓴다. 카드 전체를 물들이면 진행률이 안 읽힌다.

만들기 화면(`GoalCreateScreen`)은 하단 탭 위를 덮는 전체 화면이다. 폼이라 장식이 없다.

```
×  새 목표
─────────────────────────────────────────────
무엇을 이루고 싶으세요?
[ 주 3회 운동하기                          ]
어떻게 할까요?
[  한 번만  ][  반복해서  ]                    ← SegmentedChoice
  얼마나 자주?
  [주][달]  [ −   4회   + ]                   ← CountStepper
  몇 주 동안?
  [ −      4주      + ]
  4주 동안 총 16번 하게 돼요.                   ← 서버 target_count 와 같은 식
한 번에 얼마나 걸리나요? (선택)
[ 분 단위로 입력                            ]
색 (선택)
⊘ ● ● ● ● ●                                  ← 팔레트 안에서만 고른다
─────────────────────────────────────────────
[ 목표 만들기 ]
```

설계에서 정한 것

- **반복을 고르는 순간 주 3회를 미리 채운다.** 서버가 `type=recurring` 이면 `frequency` 를
  요구하므로, 빈 칸을 만들어 두고 오류로 알리지 않는다.
- **빈도·기간은 스테퍼로 받는다.** 1~14회, 1~52주라 범위가 좁고 자주 바꾼다. 키보드를 띄울 값이 아니다.
- **색은 팔레트 안에서만 고른다.** 자유 색상 선택기를 주면 화면 전체의 색 규칙이 무너진다.
- **총 횟수를 미리 보여 준다.** `times × weeks` 로 서버의 `target_count` 와 같은 식이다.
  숫자를 다 채우고 나서야 무엇을 약속했는지 알게 되면 늦다.

상태: 제목 비었을 때 · 50자 초과 · 소요시간 범위 밖(1~1440) 을 보내기 전에 잡는다.
서버 `VALIDATION_ERROR` 는 `details` 를 필드에 붙이고, 필드로 지목할 수 없으면 `FormErrorBanner` 로 띄운다.
제출 중에는 모든 컨트롤이 비활성이고 버튼이 스피너로 바뀐다.

아직 없는 것: 목표 상세 · 수정 · 보관 · 삭제 화면.
데이터 계층([`goal_repository.dart`](../lib/features/goal/data/goal_repository.dart))은
서버의 전체 CRUD 를 이미 덮고 있어 화면만 얹으면 된다.

### 3.6 통계 — **구현됨**

**목적** — "요즘 어떻게 하고 있나" 를 한 번에 본다. 숫자를 늘어놓지 않고 달성률 하나만 크게 둔다.

```
[최근 7일] [최근 30일]        기간 (SegmentedChoice)

┌───────────────────────────┐
│  68 %              9.9–9.15│   PaperCard — 이 화면의 유일한 카드
│  25개 중 17개를 끝냈어요     │
│  들인 시간 10시간 40분       │
└───────────────────────────┘

지금 연속        가장 길었던 연속      평면 타일 2개 (강조는 왼쪽만)
  7일              12일

날짜별 달성률                        카드 밖 평면
  ▁ ▃ █ ▅ ▂ █ █                    100% 민트 · 그 아래 앰버 · 0 은 빈 트랙
  월 화 수 목 금 토 일

끝낸 시간대       9시쯤 가장 많이 끝냈어요
  22시 ████████ 6                  기록 있는 시간대만, 많은 순 5줄

자주 미룬 것      미루는 건 실패가 아니에요. 다만 눈에는 보여야 해요.
  논문 읽기                 [3번]
```

- 기간은 **오늘로 끝나는 최근 N일**이다. 그룹 순위(달력 주)와 규칙이 다르다 — 명세가 그렇다.
- 24시간을 다 그리면 대부분 빈칸이라 읽히지 않는다. 기록이 있는 시간대만 가로 막대로 둔다.
- 기록이 하나도 없으면 막대 대신 빈 화면 한 장으로 끝낸다.

### 3.7 그룹 — **구현됨**

**목적** — 아침에 선언하고 저녁에 확인한다. 못 한 것도 같이 보인다.

목록은 카톡 방 목록과 같은 역할이라 **미확인 수와 마지막 활동**이 가장 중요하다.
연속 기록은 0일 때 적지 않는다. 시작하기도 전에 0을 크게 보여 줄 이유가 없다.

```
그룹                                   [코드로 참여]

┌───────────────────────────┐
│ 3학년 개발조            ③  │  미확인 배지 (coral)
│ 3/6명 · 2시간 전   [2일 연속][방장] │
└───────────────────────────┘
                              (+) 새 그룹
```

상세는 하루의 흐름을 그대로 탭 순서로 뒀다.

| 탭 | 내용 |
| --- | --- |
| **오늘** | 그룹 연속 기록 카드 + 선언 버튼 + 구성원별 선언 현황 |
| **피드** | 사용자별·날짜별 묶음. 인증샷과 **못 한 항목**을 한 카드에 |
| **순위** | 기간(이번 주/달/전체) + 달성률 순. 미선언자도 0% 로 남는다 |

**선언은 되돌릴 수 없다.** 그래서 확인 다이얼로그를 따로 띄우지 않고, 고르는 시트
맨 위에 그 사실을 먼저 적는다. 버튼 문구도 "n개 선언하기" 로 숫자를 박는다.

```
오늘 뭘 하겠다고 말할까요
선언하면 잠겨요. 제목을 바꾸거나 지울 수 없고, 하루에 한 번만 할 수 있어요.

  ☑ 운동하기                   60분
  ☐ 논문 읽기                  90분

        [ 1개 선언하기 ]
```

인증샷 상세(리액션·댓글)는 시트로 연다. 리액션은 사용자당 하나라 네 개를 한 줄에 두고
**지금 누른 것만 칠한다**. 같은 걸 다시 누르면 취소, 다른 걸 누르면 교체다.

### 3.8 계획량 안내 — **구현됨**

홈의 오늘 자리에만 붙는 배너다. **평소에는 아무것도 보이지 않는다.**
근거가 얇거나(실행 기록 7일 미만) 계획이 평소 수준이면 서버가 조용히 넘어간다.

```
┌───────────────────────────┐
│ ⓘ 오늘 계획, 조금 많아요      │  amberSurface
│ 지난 14일간 한 시간 이상 걸리는 │
│ 일을 두 개 넘게 끝낸 날은      │
│ 이틀뿐이었어요...            │
│ 평소 하루 95분 · 오늘 210분   │  판정 근거를 같이 적는다
│ [2개 내일로]  [그냥 할게요]    │  선택지를 같은 크기로
└───────────────────────────┘
```

경고가 아니라 제안이다. 빨강이 아니라 앰버를 쓰고, 근거를 함께 적는다.
어디서 나온 말인지 보이지 않으면 잔소리가 된다.

### 3.9 아직 만들지 않은 화면

| 화면 | 상태 |
| --- | --- |
| 인증샷 촬영·업로드 | `/uploads/presign` 이 Firebase 자격증명 없이는 503. 조회·댓글·리액션은 동작한다 |
| 목표 상세·수정 | 목록과 만들기까지만 |
| 알림 · 설정 | 계획에 없음 |

## 5. 상태와 예외

모든 목록·시트는 아래를 갖는다.

| 상태 | 처리 |
| --- | --- |

| `error` | [`ErrorView`](../lib/core/widgets/error_view.dart) — 서버 문구 + `다시 시도`. `onDark` 로 네이비 면 대응 |
| `offline` | `ApiException.isNetworkProblem` → 같은 ErrorView. 재시도가 의미 있는 유일한 오류다 |
| `disabled` | 버튼 `fill` + `disabled`. 선택 0개면 `추가할 항목을 골라 주세요` |

투두 고유 상태

| 상태 | 표시 |
| --- | --- |
| `pending` | 빈 원 + 잉크색 제목 |
| `completed` | `mintInk` 체크 + 취소선 + `disabled` 제목 |
| `deferred` | `[미룸]` 칩 (warn) |
| `skipped` | `[건너뜀]` 칩 (neutral) |
| `declared` / locked | `[선언]` 칩 (active) + 자물쇠. 수정·삭제 시 스낵바로 이유를 말한다. **완료 체크는 막지 않는다** |
| `unknown` | 서버가 보낸 원문을 그대로 칩에 노출. 조용히 숨기면 아무도 눈치채지 못한다 |

음성·AI 상태

| 상태 | 표시 |
| --- | --- |
| `recording` | 마이크 버튼 활성 + 받아 적히는 문장 실시간 표시 |
| 마이크 불가 | `coral` 문구 + `글로 적을게요` 로 유도 |
| AI 분석 중 | 마스코트(aiPlan) + `말씀하신 걸 정리하고 있어요` |
| `AI_UNAVAILABLE` | `말한 그대로 추가할게요` 버튼으로 빠져나갈 길을 준다 |
| `AI_QUOTA_EXCEEDED` | `조금 쉬었다 할까요?` + 그대로 추가 |
| 자격 만료(401) | 토큰을 지우고 인트로로. 재시도해도 안 되는 것에 재시도를 권하지 않는다 |

## 7. 화면 기준 검수

Pixel 7 에뮬레이터(Android 16)에서 `adb shell wm size` · `wm density` 로 논리 해상도를 바꿔 실측했다.

| 기준 | 설정 | 결과 |
| --- | --- | --- |
| **412 × 915 dp** | 1080×2400 @ density 420 (기기 기본) | 통과 |
| **360 × 800 dp** | 720×1600 @ density 320 | 통과 |

확인한 항목

- **오버플로 없음.** 두 해상도 모두 노란 줄무늬(RenderFlex overflow)가 뜨지 않는다.
- **주간 스트립 7칸.** 360dp 에서 칸 너비 (360−40)/7 ≈ 45.7dp. 32dp 링과 두 자리 숫자가 들어간다.
- **요약 카드.** 360dp 에서 `25% · 4개 중 1개 · [3개 남음]` 한 줄이 줄바꿈 없이 들어간다.
- **터치 영역.** 체크박스 24dp 그림 + 행 상하 16dp 패딩 = 56dp. FAB 56dp. 하단 탭 62dp.
- **좌우 정렬.** 스트립·요약 카드·목록이 모두 `screenH = 20dp` 에 맞는다.

검수 중 고친 것

- 주간 스트립의 좌우 여백이 12dp 라 아래 요약 카드(20dp)와 어긋났다. 선택된 날의 배경이
  화면 밖으로 새어 나간 것처럼 보였다. `screenH` 로 맞췄다.

남은 것

- **AI 초안 시트가 길어질 때.** 초안이 5건을 넘고 키보드가 올라오면 목록이 좁아진다.
  `Flexible` + `shrinkWrap` 이라 스크롤은 되지만, 360dp 에서 한 번에 2건 정도만 보인다.
  실사용 표본이 쌓이면 시트를 전체 화면으로 올릴지 정한다.
- **가로 모드** 는 검수하지 않았다. Android-first 세로 전용으로 본다.
